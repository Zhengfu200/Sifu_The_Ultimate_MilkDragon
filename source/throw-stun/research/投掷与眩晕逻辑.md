# 《师父》投掷物与眩晕逻辑

本机 Epic 版的投掷物命中后进入通用受击流程。普通命中可以产生按帧计算的受击硬直。符合攻击属性与防御抗性判定的命中可以进入 `Dizzy` 战斗状态，这个状态有独立计时。本记录来自离线静态分析。 [蓝图字节码](blueprint.kismet.json) · [带符号反汇编](native.asm)

## 硬直与眩晕

**普通受击硬直。** `FHitImpact::MakeAppliedImpact` 按 `m_bUseNbFrameStuned` 选择自定义帧数或默认数据，将 `m_iNbFrameStuned` 写入 `FAppliedHitImpact`。普通分支在 `GenerateImpact` 中用帧数乘以 `1/60` 秒，写入 `FImpactResult::m_fStunTime`。现有防御状态或暴击等条件还能修正该值。特殊命中如 `Dizzy` 可从防御数据库的反应配置取 `m_HitReaction.m_fHittedDuration`，覆盖初始硬直时长。该字段描述进入状态时的受击反应。 [命中帧数](native.asm:4241) · [帧数换算](native.asm:5346) · [特殊反应硬直](native.asm:6007)

**进入 `Dizzy`。** 对通过过滤、未被格挡的常规角色命中，`ComputeImpactType` 从命中盒行取当前适用的 `FAttackPropertyLevel`，将三个攻击属性等级与目标当前战斗状态对应的抗性阈值逐一比较。等级需要严格大于抗性。代码优先分流推开和击倒，再检查眩晕属性。目标已经处于 `Dizzy` 时，`m_bAllowDizzyOnTopOfDizzy` 或 `m_bSuperDizzyAvailable` 可允许再次判为 `Dizzy`。保留当前状态时长的配置也可能把这次反应降为普通命中。 [属性比较及状态选择](native.asm:6169) · [重复眩晕限制](native.asm:6226)

```cpp
// 根据机器码整理的伪代码。展示有抗性数据库时的普通未格挡分支。
levels = hitBox.row.GetAttackPropertyLevel(targetDefense);
allow = compareLevelsAgainstStateResistance(levels, targetDefense, resistanceDB);

type = Hit;
if (allow.push) {
    type = Push;
} else if (allow.knockdown) {
    type = resolveKnockdownAgainstExistingState();
} else if (allow.dizzy &&
           (!targetAlreadyDizzy ||
            reaction.m_bAllowDizzyOnTopOfDizzy ||
            impact.m_bSuperDizzyAvailable)) {
    type = Dizzy;
}
return checkKeepCurrentStateThreshold(type, levels, targetDefense);
```

`ApplyImpact` 调用 `UpdateFightingStateFromImpact`。该函数把 `EImpactType::Dizzy`（7）映射为 `EFightingState::Dizzy`（4），再经 `ApplyFightingStateFromImpact` 和 `PushFightingState` 建立防御组件的状态条目。存在 `m_bSuperDizzyAvailable` 时还会带上对应的子状态。该标志由 `GenerateImpact` 核对目标是否允许超级眩晕，以及当前槽值加本次 `m_fSuperDizzyDamage` 是否到达槽上限。 [写入超级眩晕标志](native.asm:5160) · [影响类型到状态](native.asm:7774) · [推入状态](native.asm:8184)

## 眩晕状态时长

`FFightingStateElement::m_fStateDuration` 保存战斗状态时长。`BPF_GetFightingStateTimeLeft` 返回该值减去 `m_fElapsedTime`，并通过输出参数返回状态是否存在、是否无限。常规数据库路径对 `Dizzy` 使用 `UAttackPropertiesResistanceDB::m_DizzyReaction.m_Movement.m_fDuration`，其中反应配置位于数据库对象偏移 `0x290`，时长位于反应配置偏移 `0x1c`。 [数据库状态计时](native.asm:8239) · [保存时长](native.asm:8537) · [查询剩余时间](native.asm:8671)

```cpp
// ApplyFightingStateFromImpact 中 Dizzy 时长的主要路径。
// 省略附加时长的来源，以及永久状态与跨状态交互的细节。
if (state == Dizzy && subState == SuperDizzy) {
    duration = addedDuration + resistanceDB.m_SuperDizzyReaction.m_fMandatoryDuration;
} else if (hitAnimation && (dizzyLevel == 0 || impact.type == Hit)) {
    duration = hitAnimation.duration + impact.m_fInstigatorFreezeDuration;
} else if (levels.m_bUseCustomDuration) {
    duration = levels.m_fCustomDuration;
} else if (levels.m_bUseHitAnimDuration && hitAnimation) {
    duration = hitAnimation.duration + impact.m_fInstigatorFreezeDuration;
} else {
    duration = retainedOrDatabaseStateDuration(...) + addedDuration;
}
defense.PushFightingState(state, ..., duration, ...);
```

已有同类状态、抵抗反应的保留规则及 `StructureBroken` 交互都可能更改最终时长。上面的顺序记录了程序可选的时长来源，具体投掷物走哪一条还取决于它的命中盒行和目标的抵抗数据。 [时长分支](native.asm:8019) · [已有状态及破防处理](native.asm:8055)

## 玩家蓝图

- 在 `ExecuteUbergraph_BP_FightingPlayer` 内存偏移 `20611`，`BPE_ThrowableHit` 先调父类事件，再于 `20630` 调用 `AnyHit`。这段是玩家作为被命中角色时的蓝图响应。
- `DizzyStart` 入口为 `20412`，检查状态值 `4`。状态进入分支调用防御组件的 `BPF_GetFightingStateTimeLeft`，把剩余时长传给 `OnDizzyStarted`。进入和退出分别调用 `EnableDizzyPP` 和 `Disable Dizzy PP`。
- `OnThrowItemOrder` 的蓝图实现检查关卡并累计 `ThrowEE_Trophy` 成就。实际投掷在上文的原生动画通知路径中执行。

## 来源与待核对的数值

- 原生部分读取本机 `Sifu-Win64-Shipping.exe` 和相邻的 `.pdb`。地址为映像首选基址 `0x140000000` 下的 VA。DbgHelp 以精确符号匹配打开映像，反汇编包含 PDB 解析出的直接调用目标及相关字段偏移。EXE 的 CodeView 记录为 `fdd64e0fb9ed44798fd8efe0038b919d`，age 为 1。
- 蓝图来自工作区已有的原版参考 `.uasset/.uexp`。UAssetAPI 的二进制往返比对通过。JSON 记录两份输入文件的 SHA-256、函数字节码和事件图入口偏移。
